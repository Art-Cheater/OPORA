# Mercury 230 protocol implementation

Основные источники производителя:

- НПК «Инкотекс», «Меркурий 230. Руководство по эксплуатации
  АВЛГ.411152.021 РЭ», редакция 05.2026:
  https://doc.incotexcom.ru/hardware/230/
- НПК «Инкотекс», «Протокол Меркурий. Описание команд от 03.11.2023»:
  https://doc.incotexcom.ru/protocol/mercury/

Реализация находится в `app/modem_gateway/mercury230.py` и использует только
существующий live ATM21 transport. Site-packages не модифицируются. Все команды
read-only и проходят через whitelist `app/modules/irz/commands.py`.

Точная полная маркировка физического Mercury 230 пока неизвестна. Команда
`08 12` безопасно читает feature flags, но не позволяет достоверно восстановить
всю строку с корпуса. Поэтому администратор может указать маркировку после
физического обнаружения serial; источник хранится как `MANUAL`.

Полная таблица exact requests, scaling, units и статусов проверки находится в
`MERCURY_V2_COMMANDS.md`. Новые мгновенные команды специально не входят в
default poll: их следует проверять на реальном приборе по одной в порядке
U → I → f → P → Q → S → cosφ → angles. До этого они имеют
`physical_verified=false`.

Не реализованы без физической проверки модификации: энергия/тарифы, stop-frame,
профили, ПКЭ, события и диагностика. Это предотвращает отправку десятков
неподтверждённых запросов и публикацию неверно масштабированных значений.

## Telemetry storage

`IRZMeter.latest_snapshot` обслуживает быстрый UI. Один логический poll создаёт
одну `IRZMeterSnapshot`, а не строку на каждую величину. Индексы
`(meter_id, captured_at)` и `captured_at` предназначены для range queries и
будущего retention job. При 600 приборах и минутном интервале верхняя оценка —
864 000 snapshot rows/day. Автоматический scheduler и destructive cleanup пока
не включены: новые команды сначала должны пройти физическую верификацию, а сроки
retention должны задаваться конфигурацией, не константой в коде.
