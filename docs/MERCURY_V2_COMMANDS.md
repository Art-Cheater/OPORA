# Mercury 230: реестр read-only команд

Источники:

- НПК «Инкотекс», «Описание системы команд приборов учета Меркурий», версия 06.2024
  (далее — «протокол»):
  https://www.incotexcom.ru/files/em/docs/merkuriy-sistema-komand-ver-1-ot-2024-08-30.pdf
- «Меркурий 230. Руководство по эксплуатации АВЛГ.411152.021 РЭ»:
  https://doc.incotexcom.ru/hardware/230/
- `mercury-base 1.6` — CRC, адресация V2 и парсеры серийного номера, версии ПО и
  множителей тайм-аута. Остальные команды реализованы в
  `app/modem_gateway/mercury230.py`; site-packages не изменяются.

## Общий формат

- Кадр: `адрес` + `данные` + CRC16 MODBUS (младший байт первым). В примерах ниже
  адрес `00` — универсальный адрес, на котором отвечает установленный счётчик.
  Адрес `00` запрещён для записи, поэтому write-команды не реализуются вообще.
- Ответ-статус: 4 байта `адрес + статус + CRC` (§1.3): `01` — недопустимая команда
  (`UNSUPPORTED`), `02` — внутренняя ошибка, `03` — уровень доступа, `05` — канал
  не открыт (`CHANNEL_NOT_OPEN`).
- Граница кадра определяется ожидаемой длиной ответа, а не первым CRC-валидным
  префиксом (`match_mercury_frame`): у ответа `00 00 01 00 01 B4 00` 6-байтный
  префикс тоже имеет верную CRC.
- Канал связи уровня 1 (§2.2.2, «потребитель», только чтение) открывается
  командой `01 01 <пароль 6 байт>` при первом ответе `05`. Пароль берётся из
  `MERCURY_LEVEL1_PASSWORD` (по умолчанию заводской «111111»), кодировка — из
  `MERCURY_PASSWORD_ENCODING` (`auto`: сначала по байту на цифру, затем ASCII,
  приложение В). В журналах обмена байты пароля заменяются на `2A`.
- 3-байтные значения (рис. 4.27): порядок 1-й, 3-й, 2-й байт; в 1-м байте
  бит 7 — направление активной, бит 6 — реактивной мощности.
- 4-байтные значения энергии (рис. 4.11): порядок 2-й, 1-й, 4-й, 3-й байт;
  `FF FF FF FF` — значение недоступно (`null`).

счётчиком. Без живого обмена статус PHYSICALLY VERIFIED не ставится.

Журналы `events`: `01` включение/выключение счётчика; `03`–`05` напряжение
фаз 1–3; `17`–`19` ток фаз 1–3; `02` коррекция часов (до/после); `12`
вскрытие/закрытие; `1A` магнитное поле; `06` превышение лимита мощности; `13`
перепрограммирование (дата, число запросов, позиционный код); `14` слово
состояния (время + 6 байт). Неподдерживаемый журнал помечается `UNSUPPORTED`,
остальные читаются дальше; после двух таймаутов подряд чтение прекращается.

Массивы `energy_archive` (табл. 4.6): `reset` 0, `year` 1, `prev_year` 2,
`month` 3 (+ номер месяца 1–12), `day` 4, `prev_day` 5. Тариф 0 — сумма.
Команда 18h (расширенные суточные массивы) не используется: протокол относит её
к 234/236.

## Штатный опрос

Порядок (`POLL_ORDER` в `app/modules/irz/commands.py`): серийный номер,
версия ПО, Кн/Кт, U, I, частота, P, Q, S, cos φ, углы, энергия от сброса,
энергия по тарифам, время, слово состояния. Журналы и архивы в каждые
10 минут не читаются — только по запросу.

Стоп-кадр (`03 08` + `08 14`) не используется: `03 08` относится к группе
записи, по адресу `00` запись запрещена, а фиксация попадает в журнал
перепрограммирования. Текущие значения читаются командами `08 16` и `08 11`.

## Нужна физическая проверка

- Все команды, кроме серийного номера и версии ПО.
- `transformation_ratios`: в старом захвате был 6-байтный префикс
  `00 00 01 00 01 B4`, обрезанный старой эвристикой. Полный 7-байтный кадр
  `00 00 01 00 01 B4 00` восстановлен по CRC, ожидаемо Кт = 1; нужен повторный
  захват.
- Поддержка `08 16` конкретной модификацией: при `UNSUPPORTED` выполняется
  автоматический переход на пофазное чтение `08 11`.

Инструмент проверки запускается в web-контейнере и идёт через живую сессию
ATM21:

```bash
docker compose exec web flask irz-verify --imei <IMEI> --command voltage_phases
docker compose exec web flask irz-verify --imei <IMEI> --command all --save /tmp/mercury.json
```

Для каждой команды выводятся TX, RX, результат проверки CRC и разобранные
значения. Fixture сохраняется без IMEI.

## Добавление команды

До включения команды нужно зафиксировать раздел протокола, точные байты
запроса, длину и структуру ответа, порядок байт, знак, масштаб и единицы.
Затем добавить тесты: точный TX с CRC, корректный RX, короткий пакет, неверную
CRC, таймаут и статус `01`. До обмена с живым счётчиком `physical_verified`
остаётся `false`. Write-команды не добавляются.
