# Адресный справочник

Раньше подсказки брались из ручного списка `KIROV_STREETS`: улицы города,
четыре района, без домов и без деревень. Этого недостаточно, чтобы «были все
адреса». Список оставлен как запасной каталог, пока в базу не загружен
региональный справочник. Пустая таблица справочника не меняет старые подсказки.

Справочник и геокодер — разные вещи.

- Справочник отвечает, какие населённые пункты, улицы и дома существуют.
- Геокодер переводит строку в координаты и координаты в строку.

Для названий источник — ФИАС/ГАР по Кировской области (регион 43), не вся
Россия. Координаты дома можно приложить из той же выгрузки или из OSM.
Публичный Nominatim остаётся текущим геокодером по умолчанию. Для постоянной
нагрузки production его лучше заменить своим Photon на выгрузке области:
у публичного Nominatim лимит около одного запроса в секунду.

## Модель

Таблицы: `geo_settlements`, `geo_streets`, `geo_houses`, `geo_entrances`,
`geo_geocode_cache`. У записи есть `source` и `external_id`. Повторный импорт
обновляет ту же запись и не создаёт дубль. Дом хранит корпус, индекс, ФИАС и
OSM id, если они есть. Квартиры в справочник не загружаются: заявке они не нужны.

У заявки и дефекта по-прежнему свои `latitude` и `longitude`. Рядом пишется
`geocode_quality`: `MANUAL`, `EXACT`, `INTERPOLATED`, `STREET`, `SETTLEMENT`,
`UNKNOWN`. Точка уровня улицы или населённого пункта в форму сама не
подставляется: пользователь ставит её на карте.

Поиск не различает регистр и `ё`/`е`. «ул. Ленина, 10», «Ленина д.10» и
«улица Ленина дом 10» разбираются одним разбором адреса.

## Импорт

Большой импорт не выполняется при старте сайта. Команда:

```text
flask geo-import --file data/geo/kirov-oblast.ndjson --source gar
```

Файл — NDJSON, одна запись на строку. Типы: `settlement`, `street`, `house`,
`entrance`. Обязательны `type` и `external_id`. Дом ссылается на улицу полем
`street_external_id`, улица на населённый пункт — `settlement_external_id`.
Повтор запуска идемпотентен. Битая строка пропускается и считается в
`errors`, остальные строки сохраняются. Команда пишется администратором,
не из entrypoint контейнера.

Как обновлять:

- ГАР Кировской области — когда выходит новый срез, обычно раз в квартал,
  тем же `flask geo-import`.
- OSM для координат и подъездов — вместе с обновлением графа маршрутов,
  ориентир раз в квартал или после крупных изменений дорог.
- Кэш геокодера живёт в `geo_geocode_cache` и в памяти процесса. Одинаковый
  запрос наружу второй раз не уходит.

Пока NDJSON не загружен, в поиске остаётся прежний каталог улиц Кирова.
Скачать и преобразовать ГАР области должен администратор: в репозитории
готовой выгрузки нет.
